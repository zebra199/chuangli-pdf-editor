# 统一画质管理设计（单轨）

> 前置：方案 A（深度融合）已确认。本文件解决「如何用同一套方式管理画质」。

---

## 一、现状为什么是双轨（问题定义）

| 页面类型 | 现有控制方式 | 参数 |
|---|---|---|
| 图片页 | DPI | 150 / 200 / 300 + 固定 JPEG q0.9 |
| PDF 页 | 压缩档位 | none / low(q0.85,×1.6) / medium(q0.7,×1.2) / high(q0.5,×0.8)，基准 150DPI |

**问题**：
1. 同一个「清晰度/体积」诉求，要用两个不同概念表达，用户无法横向比较；
2. 混合文档里两类页面质量口径不一致，体积不可预测；
3. 体积预估需要两套算法，显示还要分开解释。

---

## 二、统一抽象：一切归约到「页面栅格密度 + 编码质量」

### 关键换算（统一的基础）

**PDF 用户单位与 DPI 的关系**：72 pt = 1 英寸，因此

```
渲染 scale = DPI / 72
```

验证：现有代码 `baseScale = 2.08` = 150 / 72 ✓ —— 说明 PDF 侧本来就是按「150 DPI」为基准在算，只是没这么表述。

### 统一公式（对两类页面完全同构）

```
页面栅格像素 = ceil(页宽pt × DPI/72) × ceil(页高pt × DPI/72)
```

| 页面类型 | 页尺寸(pt) 来源 |
|---|---|
| PDF 页 | 源 PDF 页自身尺寸；旋转 90/270 时交换宽高 |
| 图片页 | 由「图片排版」设置（纸张/方向/适配）算出的页面尺寸 |

→ **同一个 DPI，两类页面得到同一套像素密度**，可比、可预测、可统一预估。

## 三、单一旋钮：「输出画质」档位表

| 档位 | 渲染 DPI | JPEG q | PDF 页行为 | 图片页行为 |
|---|---|---|---|---|
| **矢量保真** | — | 0.95 | 保留矢量（`copyPages` + `/Rotate`），文字可选中；**镜像页例外**→按 300 DPI 栅格 | 原分辨率、不放大，q0.95 |
| **高清** | 300 | 0.90 | 栅格化 → JPEG | 栅格化 → JPEG |
| **标准（推荐）** | 200 | 0.82 | 同上 | 同上 |
| **精简** | 150 | 0.72 | 同上 | 同上 |
| **极限压缩** | 100 | 0.55 | 同上 | 同上 |

### 四条统一规则

1. **DPI 与 q 绑定**：一个档位同时决定分辨率与编码质量 → 用户只做一个选择。
2. **「矢量保真」是唯一特殊档**，且只对「未镜像的 PDF 页」生效（保住文字可选）。图片页天然是位图，此档自动退化为「原分辨率 + 最高质量」——**语义仍统一：尽可能不损失原有信息**。
3. **镜像页必须栅格**：pdf-lib 无可靠矢量镜像实现（前一轮已验证），故含镜像的 PDF 页统一走栅格；矢量保真档下用 300 DPI 兜底，视觉不损失。
4. **图片永不放大**（除非用户显式选「铺满裁切」）：有效 DPI = min(档位 DPI, 原图固有 DPI)，既避免插值模糊，也避免虚增体积。

## 四、统一导出管线（伪码）

```js
for (const page of state.pages) {
  const [pageW, pageH] = pageSizePt(page);      // PDF: 源页尺寸；图片: 排版算出的尺寸
  const { dpi, q, vector } = QUALITY[qualitySel];

  // ① 唯一的矢量路径：未镜像的 PDF 页 + 矢量保真档
  if (page.kind === 'pdf' && vector && !page.hMirror && !page.vMirror) {
    const [tp] = await outDoc.copyPages(srcDoc, [page.srcNo - 1]);
    tp.setRotation(degrees(page.rot));          // /Rotate，文字/矢量全保留
    outDoc.addPage(tp);
    continue;                                    // ← 不栅格化
  }

  // ② 其余全部走同一条栅格管线
  const effDpi = page.kind === 'pdf' && (page.hMirror || page.vMirror)
    ? Math.max(dpi || 300, 300)                  // 镜像页兜底 300 DPI
    : dpi;
  const scale = effDpi / 72;

  let canvas;
  if (page.kind === 'pdf') {
    canvas = renderPdfPageToRaster(srcPage, scale);       // pdf.js 渲染
  } else {
    canvas = renderImagePageToRaster(bitmap, pageW, pageH, effDpi, fit);  // 缩放+白底+增强
  }
  canvas = applyRotMirror(canvas, page.rot, page.hMirror, page.vMirror);  // 同一套变换
  const jpeg = encodeJpeg(canvas, q);                                      // 同一套编码
  const img = await outDoc.embedJpg(jpeg);
  const np = outDoc.addPage([pageW, pageH]);
  np.drawImage(img, { x: 0, y: 0, width: pageW, height: pageH });
}
```

**结构收益**：导出管线从「两支分叉」变成「**一个矢量特例 + 一条统一栅格干道**」，图片与 PDF 共用栅格/变换/编码/落页代码。

## 五、统一体积预估

```
bytesPerPixel(q)：0.95→0.35  0.90→0.28  0.82→0.20  0.72→0.14  0.55→0.09   (经验值，±30%)

est = Σ(非矢量页)  targetPx × bytesPerPixel(q)
    + Σ(矢量页)    源文件对应页的均摊字节
    + 固定开销 8KB
显示：「预计约 X MB（N 页，误差 ±30%）」
```

- 屏幕可显示也更统一：一套算法覆盖混合文档。
- 「矢量页」的均摊字节 = 源文件大小 × (该页在原文件中的页占比)，粗估即可。

## 六、UI 调整

| 位置 | 现状 | 改为 |
|---|---|---|
| 设置卡 1 | 「导出压缩」4 档 | **「输出画质」5 档**（矢量保真/高清/标准/精简/极限），档位名后附等效 DPI，如「标准 · 200 DPI」 |
| 设置卡 1 说明 | 单行档位说明 | 动态说明：矢量保真档提示「PDF 文字可保留选中；图片按原分辨率」 |
| 设置卡 2（新） | — | **「图片排版」**：纸张 / 方向 / 适配 / 白底增强，标注「仅影响图片页」，无图片页时置灰 |
| 预估文字 | 一套估算 | 一套统一估算（覆盖两类页面） |
| 底栏按钮 | 生成 PDF | 保持 |

**不并入画质旋钮的设置（说明理由）**：
- **纸张 / 方向 / 适配**：属于**排版**（页面尺寸与摆放），不是画质，且只对图片页有意义 → 独立分区。
- **白底增强**：属于**图像后处理**（自动色阶提白），不是分辨率/编码质量 → 独立开关，仅图片页。

这样「画质」只有一个旋钮，「排版」和「图像增强」各自独立且标注适用对象，用户心智清晰。

| 旧档位 | 等效 | 新档位 |
|---|---|---|
| 不压缩 · 矢量保真 | 矢量 | **矢量保真** |
| 低压缩 | ≈240 DPI, q0.85 | **高清**（300 DPI, q0.90） |
| 中压缩 | ≈180 DPI, q0.70 | **标准**（200 DPI, q0.82） |
| 高压缩 | ≈120 DPI, q0.50 | **精简**（150 DPI, q0.72）/ **极限**（100 DPI, q0.55） |

> 旧档位是「scale × 150DPI 基准」的隐式 DPI，新档位显式为 DPI，更好理解。

## 八、边界与风险

| 项 | 说明 | 处理 |
|---|---|---|
| 纯 PDF 文档选「标准」 | 文字会被栅格化，**失去可选中** | 说明文字明确提示；纯文字文档推荐「矢量保真」 |
| 纯图片场景选「矢量保真」 | 无「矢量」可言 | 退化为原分辨率最高质量，不报错、不困惑 |
| 图片同时开了「铺满裁切」 | 会放大 → 超出档位 DPI | 按「适配」意图优先，UI 不额外警告 |
| 大页 PDF（如 A3/海报） | 300 DPI 像素数巨大、耗时 | 保持逐页让出主线程 + 进度显示；必要时后续加「超限自动降档」 |
| 混合文档体积预估 | 两类页面混合 | 统一公式已覆盖，误差标注 ±30% |
