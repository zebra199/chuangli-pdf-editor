# 盘点报告：当前【PDF编辑器】的数据模型与链路

> 对象：`workspace/PDF编辑器/index.html`（47KB，开发版）+ `lib/`（pdf-lib 512.8KB + pdf.min.js + worker）

## 一、数据模型

```js
state = {
  files: [{ id, name, size, color, pageCount, bytes(ArrayBuffer副本) }],  // 来源 PDF 文件
  pages: [{ uid, fileId, fileName, srcNo,   // 页面流（扁平，顺序即导出顺序）
            w, h,                            // 源页尺寸 pt
            rot, hMirror, vMirror,           // 编辑操作清单（延迟写入）
            err, displayThumb }],            // displayThumb = 按操作重绘的缩略图 dataURL
  selected: Set<uid>,                        // 选中页
  history: [], future: [],                   // 撤销/重做快照栈（限深 100）
  fileSeq, pageSeq, anchorUid, dragUid,
  thumbCache: { uid: { url, w, h } },        // 原始方向缩略图位图
  fileColors: [...8 色],
  busy: false
}
```

**要点**：
- 页面流**扁平一维**，`uid` 唯一，`fileId` 关联来源文件；顺序 = 导出顺序
- **操作清单延迟写入**：编辑只改 `rot/hMirror/vMirror` 与数组顺序，导出时才真正改 PDF
- `thumbCache` 存原图位图，`makeThumbFromOps()` 用 canvas 变换即时生成 `displayThumb`
- `files[].bytes` 是源 PDF 字节副本（pdf.js 会 detach 传入 buffer，故存副本）

## 二、导入链路

```
addPdfFiles(fileList)
  → 过滤 .pdf / type=application/pdf
  → file.arrayBuffer() → bytes.slice(0) 副本（导出用）
  → pdfjsLib.getDocument({data: bytes})   // 解析页数
  → 逐页：renderPageToThumb(pdf, i, {maxW:220})   // pdf.js 渲染 JPEG dataURL
          getViewport({scale:1}) → w/h
          uid = ++pageSeq
          thumbCache[uid] = {url:thumb, w, h}
          pages.push({uid, fileId, fileName, srcNo, w, h, rot:0, hMirror:false, vMirror:false, err:false})
  → 每页 displayThumb = makeThumbFromOps(p)
  → renderList / updateFoot / refreshEditbar / updateEstimate
```

## 三、编辑链路

| 功能 | 实现 |
|---|---|
| 旋转 | `editSelected('rot')` → `rot = (rot+90)%360` |
| 镜像 | `editSelected('hMirror'/'vMirror')` → 布尔翻转（可叠加） |
| 删除 | `deleteSelected()` → 过滤 pages + 清缓存；文件页全删则移除分组 |
| 排序 | `onDrop()` HTML5 DnD → splice 重排（clientX 判插前/后） |
| 撤销/重做 | `snapshot()` JSON 快照 ⇄ `restoreSnapshot()`；`pushHistory()` 清空 future |
| 变更收口 | `afterMutate()` → 重建 displayThumb + renderList + updateFoot + refreshEditbar + updateEstimate |

## 四、导出链路

```
doExport() → 读 compressSel
  ├ mode='none' → exportVector()
  │   对每页：
  │     有镜像 → pdfjs 高 DPI(scale 3.2) 渲染 → canvas 变换 → JPEG q0.92 → embedJpg → addPage(原页尺寸)
  │     无镜像 → pdf-lib copyPages + setRotation(/Rotate) → addPage   ← 保持矢量、文字可选
  │
  └ mode=low/medium/high → exportCompressed()
      对每页：pdfjs 渲染(scale=2.08×档位系数) → canvas 变换(rot/mirror) → JPEG(档位质量) → embedJpg
              → addPage(原页 pt 尺寸，旋转 90/270 时交换 w/h)
→ doc.save() → downloadBytes() → a.download
```

- 压缩档位：low q0.85×1.6 / medium q0.7×1.2 / high q0.5×0.8（基准 scale 2.08 ≈150DPI）
- 命名：`makeOutputName(mode)`，单源文件用原名 + 档位后缀 + `_yyyyMMdd-HHmm.pdf`

## 六、可复用 vs 需改造

### ✅ 可直接复用（约 60% 代码）
1. **页面流模型 + 选中/多选 + 拖拽排序 + 撤销重做** —— 与图片工具天然同构，零改造
2. **pdf-lib 版本与参考项目完全一致**（MD5 相同），合并零冲突
3. **CSS 变量 / 卡片 / 分组头 / 底栏 / 预览遮罩 / 进度遮罩 / toast** —— 全复用
4. **pdf.js worker 内嵌机制 + 单文件构建脚本**（build_single.cjs）
5. **体积预估机制**（`estText` + 档位参数表）
6. **键盘快捷键、预览缩放拖拽、进度遮罩** 组件

### 🔧 需要改造
| # | 改造点 | 说明 | 工作量 |
|---|---|---|---|
| 1 | `pages[]` 增 `kind:'pdf'\|'image'` | 图片页字段：`bitmap, natW, natH, heic, fileSize, proxyBytes` | 小 |
| 2 | 导入分派 | `addFiles()` 按扩展名分流：`.pdf`→现有；图片→新 `addImageFiles()`（HEIC 转 JPEG、EXIF 纠正、bitmap 缓存） | 中 |
| 3 | 卡片渲染分支 | 图片页缩略图来源不同；分组头对图片的处理（图片可各自独立或归一个「图片」组） | 中 |
| 4 | 导出管线分支 | 图片页**必须转图**（走 planFor/renderCanvas）；PDF 页按档位走矢量/转图 | 大 |
| 5 | 图片页尺寸策略 | `planFor()` 五设置（纸张/方向/白底增强/适配/DPI）决定页面尺寸 | 中（可从参考项目移植） |
| 6 | 设置面板分区 | 新增「图片设置」区（5 项），与「导出压缩」区分区 | 中 |
| 7 | 体积预估分页类型 | 图片页按目标像素估、PDF 页按档位估，合并显示 | 小 |
| 8 | 新增 heic2any 依赖 | 1.3MB；单文件版体积会增至约 3.7MB | 小 |
| 9 | 命名/文案 | 导入区文案改「PDF / 图片」；输出文件名策略兼容混合 | 小 |
| 10 | 撤销/重做适配 | 快照需包含图片页字段（bitmap 不进展照，指向缓存） | 小 |

### ⚠️ 需明确的设计冲突
1. **画质控制双轨**：图片有 DPI(150/200/300)，PDF 有压缩档位。若混合导出，图片页用 DPI、PDF 页用档位 —— 需在 UI 上说明「各管各的」，或统一成一档。
2. **旋转语义**：图片页 canvas 重编码；PDF 页 `/Rotate`（矢量）或渲染旋转。视觉一致，内部实现不同。
3. **交互粒度**：参考项目每卡「左转/右转/删除」；本工具是选中式批量工具条。建议**保留选中式**（更强），不额外加卡片按钮。
4. **缩略图比例**：参考项目固定 3:4；本工具按真实宽高比。合并后建议统一按真实比例（更准确）。

## 七、结论

**深度融合完全可行**。两者底层同为「有序页面卡片流 + pdf-lib 导出」，pdf-lib 版本一致、CSS 同源。
核心改造 = **给页面流条目加 `kind` 维度**，导入分流、渲染分流、导出分流。预计改造量中等偏小（可复用 60% 以上），无架构级阻碍。
