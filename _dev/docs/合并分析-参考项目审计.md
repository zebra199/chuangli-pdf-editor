# 参考项目审计：【图片转pdf 本地小工具】

> 审计对象：`workspace/图片转pdf 本地小工具/`（index.html 27.4KB + lib/ + 点击启动.bat + 使用说明.md）

## 一、文件与依赖

| 项 | 内容 |
|---|---|
| 主文件 | `index.html`（单文件 HTML + CSS + JS，27.4KB） |
| 依赖库 | `lib/pdf-lib.min.js`（512.8KB）、`lib/heic2any.min.js`（1320.2KB，HEIC→JPEG） |
| 启动 | `点击启动.bat`（cd 到目录 + start index.html） |
| 运行方式 | 双击 index.html 或 bat；**非单文件**（依赖 lib/ 目录） |

**★ 关键发现**：参考项目的 `pdf-lib.min.js` 与 PDF编辑器 的**完全一致**（大小 525099、MD5 `DEC481B1ABD5119D3FBBD2695BDAEBB1`）。合并时 pdf-lib 只需一份。

## 二、功能清单

| 功能 | 实现方式 |
|---|---|
| 导入图片 | 拖放 / 点击选择，多选、多次添加；支持 JPG/PNG/HEIC/HEIF |
| HEIC 支持 | heic2any 转 JPEG（质量 0.92）后再解码 |
| EXIF 方向纠正 | `createImageBitmap(blob, {imageOrientation:'from-image'})`，回退 Image |
| 左转/右转 | `item.rot = (rot ± 90) % 360`，缩略图/预览/导出同步 |
| 删除单张 | 从 items 过滤 |
| 拖拽排序 | 卡片级 dragstart/dragover/drop，splice 重排 |
| 清空 | confirm 后清空 items |
| 点击预览 | canvas 渲染当前旋转态 → dataURL，滚轮缩放 + 拖拽移动 + Esc 关闭 |
| 生成 PDF | pdf-lib 逐张：renderCanvas → JPEG(q0.9) → embedJpg → addPage → drawImage |
| 体积预估 | 按目标像素数 × 原图编码密度估算，显示"约 X（N 页，±25%）" |
| 设置持久化 | localStorage `p2p_settings` |

## 三、设置项（5 个，全部影响导出）

| 设置 | 选项 | 作用 |
|---|---|---|
| 纸张 | A4(210×297) / A5(148×210) | `MM2PT=72/25.4` 换算磅值 |
| 方向 | auto（横图自动横版）/ portrait（全竖版） | 按旋转后宽高比决定页面横竖 |
| 白底增强 | none / light(clip 1.0%) / standard(clip 2.5%) | 自动色阶（灰度直方图拉白），提升扫描件清晰度 |
| 适配 | contain（完整显示留白）/ cover（铺满裁切） | 决定图片在页面上的缩放与偏移 |
| 清晰度 | 150 / 200 / 300 DPI | 决定输出栅格像素数与页面上的物理尺寸 |

## 四、数据模型

```js
items = [{ id, file, name, heic, bitmap, rot, ok, error, proxyBytes, natW, natH }]
```

- **扁平一维数组**，顺序即页序
- 每条 = 一张图片 = PDF 一页
- `rot` 仅存旋转角度（不重编码原图），导出时在 canvas 上应用
- `bitmap` 是解码后的位图（ImageBitmap / Image），驻留内存

## 五、导出链路（核心）

```
planFor(item, settings)   // 算页面尺寸(磅) + 目标栅格像素 + 摆放(offset/尺寸)
  → renderCanvas(item, plan)  // 新 canvas：白底 → 旋转 → 缩放 → drawImage → 白底增强
  → canvasToJpegBytes(cv, 0.9)  // toBlob → JPEG 字节
  → doc.embedJpg → addPage([pageW,pageH]) → drawImage({x,y,width,height})
→ doc.save() → Blob → a.download
```

**输出特性**：图片一律转 JPEG 重编码（丢失原矢量性，但图片本来就不是矢量）；每页独立尺寸（可混排横竖）；文件名 `合同PDF_yyyyMMdd-HHmm.pdf`。

## 六、界面结构（与 PDF编辑器 同源风格）

- 标题栏 `📄 照片合并 PDF` + 副标语
- 设置卡片（5 个下拉 + 体积预估文字）
- 虚线导入区 + 蓝色「选择照片」
- 卡片网格（`minmax(158px,1fr)`，缩略图 `aspect-ratio:3/4` + 序号徽标 + 文件名/体积 + 底部操作行「左转/右转/删除」）
- 固定底栏（信息 + 清空 + 绿色「生成 PDF」）
- 预览遮罩（缩放/拖拽）、进度遮罩、toast
- CSS 变量与 PDF编辑器 **完全同源**（同一套 `--bg/--card/--acc/--ok` 等）

**风格差异**：参考项目缩略图固定 3:4 竖版比例；PDF编辑器 按页面真实宽高比；参考项目操作在卡片底部行（左转/右转/删除），PDF编辑器 用顶部统一工具条（多选操作）。

## 七、与 PDF编辑器 的可融合点 / 冲突点

### 可融合（高度同构）
1. **页面流模型同构**：都是「一维有序卡片列表」，顺序=页序，都支持拖拽排序。
2. **pdf-lib 版本一致**：合并零冲突。
3. **CSS 风格同源**：配色变量、卡片、底栏、遮罩完全一致，合并后视觉无割裂。
4. **导出都是 pdf-lib 组装**：可统一为一条导出管线。
5. **都有预览/进度/toast/体积预估**：可复用同一套 UI 组件。
6. **设置持久化机制一致**（localStorage）。

### 冲突/需改造点
1. **页面尺寸策略冲突**：
   - 图片页：需要 `planFor`（纸张/方向/DPI/适配/增强 5 项设置）决定页面尺寸；
   - PDF 页：沿用原页尺寸（矢量导出）或按压缩档位转图。
   - → 需在页面流里区分 `kind: 'pdf' | 'image'`，导出时分支处理。
2. **图片页设置的作用域**：纸张/方向/DPI/增强 只对图片页有意义；PDF 页不需要。若混排，需明确「设置仅影响图片页」。
3. **旋转语义一致但实现不同**：
   - 图片页：canvas 旋转重编码（天然支持任意角度）；
   - PDF 页：`/Rotate`（矢量）或渲染旋转（转图）。
4. **压缩档位 vs 清晰度**：两个工具各有一套画质控制（压缩档位 / DPI），合并后需统一或并存，避免用户困惑。
5. **HEIC 库体积**：heic2any 1.3MB，合并后单文件会增大（若做单文件版）。
6. **图片来源是内存位图，PDF 来源是字节**：导出管线要处理两种源数据。
7. **操作粒度差异**：图片卡片每张有独立「左转/右转/删除」按钮；PDF编辑器是选中式批量工具条。合并需统一交互（建议保留选中式，同时兼容单卡操作）。

### 结论
**深度融合可行**。核心是把「页面流」的条目从 `pdfPage` 泛化为 `pdfPage | imagePage`，
编辑操作（旋转/镜像/删除/排序/撤销）对两者通用，导出时按 kind 分支。
主要工作量在：页面尺寸策略分派、设置面板分区（图片设置 vs PDF设置）、统一交互与工具条。
